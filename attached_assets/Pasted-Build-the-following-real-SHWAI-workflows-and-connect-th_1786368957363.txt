Build the following real SHWAI workflows and connect the frontend, backend, database/state, and role-based permissions properly.

IMPORTANT:

==================================================
1. NOTICES / ANNOUNCEMENTS
==================================================

Add a "Notices" section to the Student Portal.

Teachers and Principals should be able to create and publish notices.

STUDENT:
- Students can view notices relevant to them.
- Show notice title, content, author, date/time, and attachments if available.
- Clearly distinguish new/unread notices.
- Students cannot create or edit notices.

TEACHER:
- Add "Create Notice" / "New Notice" button.
- Teacher can enter:
  - Notice title
  - Notice description/content
  - Target audience
  - Optional attachment
- Teacher should be able to publish the notice.
- Teacher can see notices they have created.
- Teacher can edit/delete their own notices if appropriate.

PRINCIPAL:
- Principal should have the same notice creation functionality.
- Principal should be able to target:
  - All students
  - Specific classes/sections
  - All teachers
  - Specific teachers
  - Parents
  - Entire school
- Principal notices should appear in the relevant portals.

==================================================
2. TEACHER HOMEWORK CREATION
==================================================

ONLY TEACHERS should have the ability to create and post homework.

Add a "Homework" section to the Teacher Portal.

Add a prominent:
"+ Create Homework"

button.

The teacher should be able to create:

- Homework title
- Subject
- Class
- Section
- Description/instructions
- Due date
- Optional marks
- File attachment
- Optional reference material

The teacher should be able to publish the homework.

After publishing:
- The homework should immediately appear for the selected students.
- Students should see the homework in their Student Portal.
- Show:
  - Title
  - Subject
  - Instructions
  - Teacher
  - Posted date
  - Due date
  - Attachment
  - Submission status

Possible statuses:

- Not Started
- In Progress
- Submitted
- Late
- Reviewed

==================================================
3. STUDENT HOMEWORK SUBMISSION
==================================================

When a student opens a homework assignment, provide:

"Submit Assignment"

button.

When clicked, open a submission interface.

Allow students to submit:

- Files
- PDF
- Images/photos
- Documents where supported

The student should be able to:
- Select/upload a file
- See the selected file before submission
- Remove/replace the file
- Add an optional comment
- Submit the assignment

After submission:
- Change status to "Submitted"
- Record submission date/time
- Store the submitted file securely
- Prevent accidental duplicate submissions unless the teacher allows resubmission
- Show the student what they submitted

If the deadline has passed:
- Clearly mark the submission as late.
- Preserve the exact submission timestamp.

9. ROLE-BASED PERMISSIONS
==================================================

Implement proper role-based access.

STUDENT:
- View notices
- View assigned homework
- Submit homework
- View own submissions
- Chat with permitted teachers
- Cannot create homework
- Cannot create school notices

TEACHER:
- Create homework
- View assigned students
- View student profiles
- View student submissions
- Review submissions
- Grade/feedback where the existing gradebook supports it
- Create teacher notices
- Receive Principal notices
- Chat with assigned students

PRINCIPAL:
- Create school notices
- Create teacher/staff notices
- View/manage teachers
- View/manage students according to school permissions
- View student submissions
- Access school-wide information

Do not expose unauthorized actions simply by hiding buttons. Enforce permissions in the backend as well.
