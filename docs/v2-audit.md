# SHWAI V2 Academic Core Audit

The current repository has authenticated V1 identity, school memberships, server-derived roles, and PostgreSQL migration boundaries. Homework and submission routes exist, but their contracts still accept client-supplied identity fields for compatibility, use demo class/subject selectors, and do not yet provide assignment lifecycle, gradebook publication, assessment/question records, report cards, timetable conflict checks, or descriptive academic analytics.

The V2 implementation will focus on persisted academic records and server-side policy. V2 will not add AI tutor, AI generation, predictive intelligence, enterprise operations, or advanced AI. External file storage and Google/email/SMS providers will be represented only by configuration-aware interfaces and honest blocked states.

| V2 area              | Existing baseline                                                                                               | Required implementation direction                                                                                            |
| -------------------- | --------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------- |
| Academic structure   | V1 tables and CRUD services exist for years, classes, sections, subjects, teacher assignments, and enrollments. | Add server-scoped lookup helpers and use persisted IDs in academic records.                                                  |
| Homework             | `hw_homework` and `hw_submissions` exist with basic create/list/submit/grade actions.                           | Add lifecycle, assignment targeting, attempt history, published grade visibility, validation, and audit coverage.            |
| Gradebook            | No persisted gradebook/assessment entities.                                                                     | Add assessments, questions, grades, publication status, and result visibility.                                               |
| Online assessments   | No persisted assessment/question/attempt entities.                                                              | Add manual MCQ/subjective question management and basic timed attempts with server-side duration enforcement.                |
| Offline exams        | No dedicated records.                                                                                           | Reuse grade records with an offline-entry path.                                                                              |
| Report cards         | No persisted records.                                                                                           | Add calculated draft/published report-card snapshots from published grades and attendance.                                   |
| Analytics            | Existing V1 mock intelligence modules only.                                                                     | Add descriptive SQL aggregates from actual academic records; no predictions.                                                 |
| Timetable            | No persisted timetable records or conflict checks.                                                              | Add server conflict detection for teacher, room, and section.                                                                |
| Substitute teachers  | No persisted records.                                                                                           | Add school-scoped substitute assignment records with availability checks.                                                    |
| Calendar integration | V1 calendar events exist.                                                                                       | Link V2 homework, assessments, timetable, and report-card publication to the shared event model without duplicating records. |
| Portals              | Student and parent shells exist; teacher portal is mostly navigation.                                           | Add persisted academic summaries filtered by authenticated identity and linked-child relationships.                          |
| Engagement           | No persisted XP/achievement records.                                                                            | Add idempotent activity awards based on actual submissions, assessment completion, and milestones.                           |
| Integrations/files   | V1 metadata and configuration-required states exist.                                                            | Keep metadata, add storage abstraction and provider detection without claiming external delivery/import.                     |
| Tests                | Existing V1 unit tests cover auth/access/notice policy.                                                         | Add pure policy/validation tests and, where database configuration permits, integration tests.                               |

The strict V2 gate remains dependent on a configured PostgreSQL environment. The sandbox currently has no `DATABASE_URL` or `SUPABASE_DATABASE_URL`, so migration and database integration cannot be verified locally unless credentials are provided.
