# SHWAI data export

## Implemented workflow

Authorized owner and principal users can request school-scoped CSV or JSON exports for students, attendance, or grades. The server applies `data.export`, applies a school/user rate limit, creates an `hw_export_jobs` record, enqueues an idempotent `export` job, audits the request, and returns a job identifier. The worker queries only the authenticated school’s records, writes the artifact to private S3-compatible storage, creates a storage-object record with a 15-minute expiry, and marks the export complete.

The browser polls the server-side export status and can request a signed download URL only after the export is complete, the artifact is active, the expiry has not passed, and the request still belongs to the same school. Download requests are logged in `hw_data_access_logs`. The URL does not expose a public bucket path or storage credentials.

## Required deployment configuration

Set `STORAGE_PROVIDER`, `STORAGE_ENDPOINT`, `STORAGE_BUCKET`, `STORAGE_ACCESS_KEY_ID`, `STORAGE_SECRET_ACCESS_KEY`, and `STORAGE_REGION` in server-side secret storage. Set `MALWARE_SCANNER_URL` and `MALWARE_SCANNER_API_KEY` before enabling document downloads. Use a private bucket with public ACLs disabled, server-side encryption, lifecycle rules, and provider access logs. Never expose public bucket URLs or storage credentials.

No export is considered operationally complete until a staging test proves that the artifact is inaccessible after expiry, the signed download is school-scoped, the worker retries provider failures, and the provider/storage audit is verified. Do not paste real production exports into development or staging.
