Every supported feature must be functional across persistence, server logic, authentication, school/tenant isolation, authorization, input validation, error/configuration states, audit, real frontend/backend data flow, and tests where practical. Provider-dependent capabilities must expose CONFIGURATION_REQUIRED without fabricated success.

Security boundaries: server-derived identity; no client-selected school/role/user; school-scoped queries; role-aware student/teacher/parent/counselor/admin/owner access; approved sources cannot leak across schools; no secrets or hidden prompts; AI endpoints rate-limited, input-bounded, and audited. Required UI states: loading, empty, success, error, retry, configuration required, insufficient data, unauthorized, pending review, approved, rejected, stale data, low confidence.
