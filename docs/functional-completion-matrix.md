## Security and data boundary status

The server action layer validates input shapes, applies role checks for attendance and audit access, rejects cross-school identifiers, limits the attendance batch size, and writes a server-side audit event for every saved attendance register. This improves the existing demo boundary but is not a replacement for production authentication because the repository still derives the acting identity from a demo role selector. Production deployment must add a real identity provider, server-issued session context, school membership records, and server-side plan entitlements.

## Verification status

`npm run check`, `npm test`, focused ESLint for all files changed in this implementation, `npm run build`, and `git diff --check` pass. Browser verification confirmed the attendance route renders the persisted workflow and, without database configuration, transitions from loading to a retryable configuration error instead of claiming a successful write.
